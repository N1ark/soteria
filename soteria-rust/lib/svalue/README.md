# The value language of soteria-rust

soteria-rust's values, written in Kanon: the language is generated from the
SHARED modules of `Bv_values` (bool, exists, bitvec, float, ptr and the `view` of
the host code, in `soteria/lib/bv_values/rules/`) plus the `rust` module
(aggregates, thin/full pointers, pointer metadata, poly values), over the same
generic host stack as the C language (`Lang_make.Make`, `Typed.Make_transparent`).
It replaced the extension `Ext` of the first, hand-written generation of the
generic values (deleted: `git show fab3ed5:soteria/lib/bv_values/svalue.ml`).
`Svalue.Typed` is what the rest of soteria-rust uses.

## Layout

| file | content |
|---|---|
| `rules/lang.knl` | the language: the shared modules (their path is written ONLY here), `Var`, `Seq`, host types, ghost tags (`sptr_f sptr_t tuple enum union poly scalar aggregate any`) |
| `rules/rust.knl`, `rules/rust.kn` | host types (`'a iarray` is `Soteria_std.Iarray.t`), sorts `TEnum TUnion TTuple TArray TThinPtr TFullPtr TPtrMeta TPolyType`, leaf nodes `ThinPtr FullPtr PtrMeta Enum Tuple Array Union PolyVal ThinPtrPart FullPtrInner FullPtrMeta PtrMetaAs Field VariantField IsVariant ArrayField`; the smart constructors as Kanon `fn`s; the `extend fn` cases of the view (`operands rebuild node_cost cost learn_alts learn_value sort_operands encode_sort encode_head pp_style`). Everything is `[@no_lean]`: there is no Lean semantics for these nodes. `[@total]` makes Kanon reject a node without a case |
| `rust_types.gen.ml`, `rust_rules.gen.ml` | generated by the rules of `dune` (see `dune`: `kanon ocaml-types|ocaml rules/lang.knl`), promoted and committed, in `.ocamlformat-ignore`; dune copies them to the modules `Rust_types`, `Rust_rules` |
| `base_prims.ml`, `base_view_prims.ml` | COPIES of `bv_prims.ml`/`view_prims.ml` of the C language over `Rust_types`; patches marked `PATCH`: `rust_operands` + a case in `used_binders_iter_vars`, `pp_ty` printing the Rust sorts as `(TExtension X)` like the old derived printer, and `Stdlib.Option.bind` (this library opens `Soteria_std`). They are copies because the prims are over the types that Kanon generates for each language (`Bv_types` for C, `Rust_types` here), which differ, and OCaml cannot abstract over them without a functor, which the generated code does not use: the `PATCH` sites are the whole difference, so that a change to one is applied to the other |
| `rust_host.ml`, `rust_charon.ml`, `rust_encoding.ml`, `rust_prims.ml` | `ptag`; `ty_of_rust`, `usize_bits`, `t_as_*`; the SMT sort modules and operators; the prims of rust.kn (crate reads, exceptions, `ph_*` text heads, `iarray_*`) |
| `rust_lang.ml`, `rust_stack.ml`, `typed.ml(i)` | `Kanon_fns` composition; `Lang_make.Make`; the typed layer (`Svalue.Typed`) |
| `iface.ml` | the ONE file naming the generic stack (`Soteria.Bv_values.*`) |
| `ptr_tag.ml(i)` | the tags of the provenance of pointers |

Kanon must be the pinned one (`KANON_COMMIT_HASH`): dune finds it in the `PATH`.
The dune rules depend on the rules of the shared modules in `soteria/`.

## Tests

- `soteria-rust/test/golden`: the dump of the behaviour of `Svalue.Typed`
  (`golden.expected` is the dump of the old values, byte for byte).

The differential test of this language against the old one (random values built
through the same interface, compared structurally, with SMT text, and its
mutation self-test), and the array benchmark, lived in
`soteria-rust/test/legacy_svalue`, deleted in S7 with the old values: its results
are in the message of commit `157ae4c`.

## Deviations from the old stack

- Thin pointer and block record fields are renamed (`ptag psize palign`,
  `bvalue boffset bsize`) to avoid clashes inside the generated type group; the
  typed interface keeps the old polymorphic `block_raw` and converts.
- Old `Ptr` of Rust is `FullPtr`. Sorts print as `(TExtension X)` as before.
- `Rust_stack.K` is sealed as `Kanon_fns`; Rust code uses `Rust_lang` directly.
- `TExtension X` is the sort `X` (`match%ty` too).

## Risks / not verified

- Crate-dependent prims (`ty_of_rust`, `variant_field_ty`, `usize_bits`) run
  inside what are now Kanon fns; Charon types are hashed by `Hashtbl.hash`, as before.
- No Lean semantics for the rust nodes.
- `base_*prims.ml` are copies: replace by a shared prims functor when it exists.
