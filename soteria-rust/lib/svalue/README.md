# The value language of soteria-rust

soteria-rust's values, written in Kanon: the language is generated from the
SHARED modules of `Bv_values` (bool, exists, bitvec, float, ptr and the `view` of
the host code, in `soteria/lib/bv_values/rules/`) plus the `rust` module
(aggregates, thin/full pointers, pointer metadata, poly values), over the same
generic host stack as the C language (`Lang_make.Make`, `Typed.Make_transparent`).
It replaced the extension `Ext` of the first, hand-written generation of the
generic values (deleted: `git show fab3ed5:soteria/lib/bv_values/svalue.ml`).
`Svalue.Typed` is what the rest of soteria-rust uses.

## Layout

| file | content |
|---|---|
| `rules/lang.knl` | the language: the shared modules (their path is written ONLY here), `Var`, `Seq`, host types |
| `rules/rust.knl`, `rules/rust.kn` | host types (`'a iarray` is `Soteria_std.Iarray.t`), sorts `TEnum TUnion TTuple TArray TThinPtr TFullPtr TPtrMeta TPolyType`, leaf nodes `ThinPtr FullPtr PtrMeta Enum Tuple Array Union PolyVal ThinPtrPart FullPtrInner FullPtrMeta PtrMetaAs Field VariantField IsVariant ArrayField`; the smart constructors as Kanon `fn`s; the `extend fn` cases of the view (`operands rebuild cost learn_alts learn_value sort_operands encode_sort encode_head`). Everything is `[@no_lean]`: there is no Lean semantics for these nodes. `[@total]` makes Kanon reject a node without a case |
| `rust_types.gen.ml`, `rust_typed.gen.ml`, `rust_rules.gen.ml` | generated by the rules of `dune` (see `dune`: `kanon ocaml-types|ocaml-typed|ocaml rules/lang.knl`), promoted and committed, in `.ocamlformat-ignore`; dune copies them to the modules `Rust_types`, `Rust_typed`, `Rust_rules`. The tags of the sorts of `Typed.T` (`sptr_f sptr_t tuple enum union poly`) are aliases of `Rust_typed.Tag`; their unions (`scalar aggregate any`) are written in `typed.ml` |
| `rust_prims.ml` | `Prim.Make` (the primitives shared with the C language) applied to `Rust_types`, and the prims of rust.kn |
| `rust_host.ml`, `rust_charon.ml`, `rust_encoding.ml` | `ptag`; `ty_of_rust`, `usize_bits`, `t_as_*`; the SMT sort modules and operators, `pp_ty` |
| `rust_pp.ml` | the pretty-printer of the Rust language, `K.pp`, written by hand over `Rust_types`: the shared nodes as the C language prints them, and the nodes of rust.kn |
| `rust_lang.ml`, `rust_stack.ml`, `typed.ml(i)` | `Kanon_fns` composition; `Lang_make.Make`; the typed layer (`Svalue.Typed`) |
| `iface.ml` | the ONE file naming the generic stack (`Soteria.Bv_values.*`) |
| `ptr_tag.ml(i)` | the tags of the provenance of pointers |

Kanon must be the pinned one (`KANON_COMMIT_HASH`): dune finds it in the `PATH`.
The dune rules depend on the rules of the shared modules in `soteria/`.

## Deviations from the old stack

- Thin pointer and block record fields are renamed (`ptag psize palign`,
  `bvalue boffset bsize`) to avoid clashes inside the generated type group; the
  typed interface keeps the old polymorphic `block_raw` and converts.
- Old `Ptr` of Rust is `FullPtr`. Sorts print as `(TExtension X)` as before.
- `Rust_stack.K` is sealed as `Kanon_fns`; Rust code uses `Rust_lang` directly.
- `TExtension X` is the sort `X` (`match%ty` too).

## Risks / not verified

- Crate-dependent prims (`ty_of_rust`, `variant_field_ty`, `usize_bits`) run
  inside what are now Kanon fns; Charon types are hashed by `Hashtbl.hash`, as before.
- No Lean semantics for the rust nodes.
- `base_*prims.ml` are copies: replace by a shared prims functor when it exists.
