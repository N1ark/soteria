# Tests of the new stack (WP3c)

Ports of the three test programs of the old stack to the NEW stack: the language
generated by Kanon (`Bv_new.Types/Rules/Prims`) + the generic functors of
`iface/` (`Lang_v.Make`, `Typed_v.Make`) over one implementation of `Kanon_fns`.

| dir | port of | what |
|---|---|---|
| `stack/` | - | library `new_stack`: the ONE place that chooses the `Kanon_fns` implementation |
| `golden_new/` | `bv_golden/` | the golden dump (same generator, same printing) |
| `fuzz_new/` | `bv_fuzz/` | soundness of the smart constructors against RAW nodes, checked by Z3 |
| `eval_new/` | `bv_values/test_eval.ml` | the 7 alcotest cases of `Eval` (Exists, Ite) |

## Switching the `Kanon_fns` implementation

Only `stack/new_stack.ml`:

```ocaml
module K : Kanon_fns.Kanon_fns with type t = Types.t and type ty = Types.ty =
  Kanon_ref        (* <- the hand-written reference (iface/check/kanon_ref.ml) *)
```
Replace `Kanon_ref` by the generated view, e.g.
`struct include Bv_rules include Host end` (see INTERFACES.md section 2) and add
the library of the generated module to `stack/dune` (`kanon_ref` is compiled there
by `(copy_files ../iface/check/kanon_ref.ml)`, with the same flags as `iface/check`;
drop it from `modules` when it is no longer needed). The three test directories
only mention `New_stack.{Typed, L, Lang}` and never the implementation.

## Running

```sh
dune build soteria/tests/bv_new/golden_new soteria/tests/bv_new/fuzz_new soteria/tests/bv_new/eval_new
dune test soteria/tests/bv_new/eval_new                      # 7 tests, instant
soteria/tests/bv_new/golden_new/golden_new.sh OUT [SEED [REFERENCE]]
QCHECK_SEED=42 QCHECK_TEST_COUNT=5000 dune exec --no-build -- soteria/tests/bv_new/fuzz_new/fuzz_bool.exe   # (and fuzz_bv.exe)
dune build @soteria/tests/bv_new/fuzz_new/slow-tests-new     # 4+4 parallel instances, 5000 each
dune build @soteria/tests/bv_new/fuzz_new/very-slow-tests-new # same, 15000 each
```
(`dune exec` of the fuzzers works from any directory; the `fuzz_*.exe` need `z3` on the PATH.)

### golden_new

`golden_new.ml` is `bv_golden.ml` with ONLY the shim at the top changed
(`module Typed = New_stack.Typed`). The reference dump of the old stack at f52223c
is `golden-c-f52223c.txt` (md5 `0ba771344340949e770f1b3efb11b844`, seed 42,
44037 lines, not committed). Expected: identical except for 6 lines, the
location text printed by `Printexc.to_string` of the assertion of `mk_bv`
(the generator creates an out-of-range literal on purpose; `fact raised File
"soteria/lib/bv_values/svalue.ml", line 374...` becomes `File
"soteria/tests/bv_new/bv_prims.ml", line 32...`; same assertion: the range
check). `golden_new.sh OUT 42 REFERENCE` normalises that location on both sides
and compares; the coverage tables on stderr differ only by `minor_words`. Also
compared (normalised) with a build of the old `bv_golden.exe` for seeds 1, 7, 123,
2024 and with `BV_GOLDEN_GC=1`: identical. About 2.3 s.

### fuzz_new

`Direct` builds raw nodes (`Bv_new.Types.node (Op2 (Eq, a, b)) ty`, `Op1`, `Op3`,
`OpN`), the checked-operation assumptions are collected independently of the
rules (own `checked_has`), `Fuzz_common` uses
`Soteria.Solvers.Z3.Make (Encoding.Make (New_stack.Lang))`: the smart version
(`Eval.eval ~force:true`, i.e. the rules through `rebuild`) is compared with the
raw term by Z3 (`not (smart = direct)` under the assumptions: must be unsat).
It is an independent soundness oracle of the rules of the new Kanon (the
differential tests only say "same as old"). Environment: `QCHECK_SEED`,
`QCHECK_TEST_COUNT` (default 5000). Timings: see the end of this file.

### eval_new

`test_eval_new.ml` is `test_eval.ml` over `New_stack.L.Svalue` / `New_stack.L.Eval`
(the generic `Eval_v`): Exists substitutes free variables, does not substitute
bound ones, unchanged = physically equal, Ite guard replaced / literal / lazy
branch evaluation / unchanged.

## Not covered

`Expr.Subst.apply`/`learn` and the encoding are covered by the golden dump only
(and by `iface/check`); no test of Rust-specific nodes; no GC-stress variant of
the fuzzers; the golden of the old stack is not regenerated by dune (compare by
hand with `golden_new.sh`).

## Results (seed 42, 4 cores, the four runs of a count in parallel)

| test | count | new stack | old stack |
|---|---|---|---|
| fuzz_bool | 5000 | pass, 36 s | pass, 36 s |
| fuzz_bv | 5000 | pass, 29 s | pass, 28 s |
| fuzz_bool | 50000 | pass, 495 s | pass, 492 s |
| fuzz_bv | 50000 | pass, 420 s | pass, 415 s |

No `Z3 returned Unknown` in any of these runs. Sanity of the oracle: with the
rule `a - (-b) -> a + b` of `bv_sub` mutated into `a - b` in a scratch copy of
`bv_rules.gen.ml`, `fuzz_bv.exe` (seed 42) fails. golden_new: about 2.3 s;
eval_new: instant (7 tests).
